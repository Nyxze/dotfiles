# Slides

Slides and presenter notes stand on their own: no repository paths, internal
document codes, or repeated slogan.

## Titles and labels

- Use natural, descriptive titles.
- Explain technical shorthand in context.
- Use short noun or action labels in tables.

## Technical cases

- Introduce each technical case with its business purpose.
- Show concrete before/after changes when explaining technical work. Highlight
  the changed code and explain the diagnosis that motivated it.
- Keep interim comparisons cumulative and limited to changes already
  explained.
- Name database indexes with the actual column identifiers. Preserve key
  order, `INCLUDE` columns, and partial-index predicates.

## Presenter notes

Write oral notes in plain, spoken language.

## Closing

Connect each change to its use case, measured effect, and retained or
rejected decision. Keep unfinished work out of the closing slide.
