# Hyprland Lua migration plan

Target: installed Hyprland 0.56.2. Preserve desktop behavior, appearance,
shortcuts, workspace ownership, and display management.

## Baseline and scope

- Repository refs fetched; working tree was clean on `main` at planning time.
- Installed and running Hyprland: 0.56.2. Live `hyprctl configerrors` is empty.
- Repository `.config/hypr/` and the live directory match. The shared
  `endfield.conf` palette also matches its live copy.
- The active entry point loads six `.conf` modules: `init`, `env`, `keybinds`,
  `settings`, `monitors`, and `workspaces`.
- The existing `monitors.lua` is generated by nwg-displays and is not loaded
  by this entry point. Its fixed positions and HDMI mode differ from the
  active monitor rules. It must not become active accidentally.

Hyprland's Lua parser changes IPC as well as configuration syntax. In 0.56.2,
`hyprctl keyword` rejects Lua sessions, and `hyprctl dispatch` interprets its
argument as a Lua dispatcher expression. Converting config files alone would
break desktop controls. See the [0.56.2 IPC implementation](https://github.com/hyprwm/Hyprland/blob/v0.56.2/src/debug/HyprCtl.cpp#L1043).

## 1. Record the behavior to preserve

Before implementation, save live binds, monitor state, workspace rules,
workspaces, animations, input devices, relevant option values, and process
counts. Record any differences between configured defaults and runtime state.

Inventory every Hyprland command in scripts, QML, idle hooks, and launchers,
including dynamically constructed commands. Check the installed Waybar and
Quickshell integrations for dispatches generated internally by those tools.
Those calls are not all visible in this repository.

Use the installed `/usr/share/hypr/stubs/hl.meta.lua` and the
[0.56.2 example](https://github.com/hyprwm/Hyprland/blob/v0.56.2/example/hyprland.lua)
to check API names and argument types. Do not import newer upstream defaults.

## 2. Convert the configuration

Keep the existing module boundaries, with an explicit `require` order in
`hyprland.lua`. Load environment and palette data before consumers, monitor
and workspace rules before display application, and register startup actions
after configuration.

| Existing configuration | Planned treatment |
| --- | --- |
| `hyprland.conf` | Lua entry point; preserve general, groupbar, decoration, animation, input, layout, and window-rule settings |
| `env.conf` | `env.lua`, using `hl.env` with unchanged values |
| `init.conf` | `init.lua`; preserve startup-only services and display application on startup/reload |
| `keybinds.conf` | `keybinds.lua`; explicit Lua dispatchers and equivalent mouse, release, transparent, repeat, and locked flags |
| `settings.conf` | `settings.lua`; explicit palette import and ordinary Lua values where still used |
| `monitors.conf` | Hand-maintained `displays.lua` preserves active rules; generated `monitors.lua` remains unloaded |
| `workspaces.conf` | `workspaces.lua`; preserve persistent workspaces 1–5 and named `Laptop` workspace |
| `theme/endfield.conf` | Retain for Hyprlock; add `theme/endfield.lua` with matching semantic tokens and alpha values |

Preserve regex semantics using Lua strings that do not consume regex escapes.
Keep the transparent native groupbar and its 24-pixel reserved height, current
animation curves, session-lock restoration, keyboard settings, and Moonlight
placement rule. Translate unusual Hyprlang booleans to actual Lua booleans.

Use startup events for Waybar, Hyprpaper, Hypridle, Quickshell, and the display
watcher. Preserve display reapplication on reload without duplicating watchers
or services. Verify event timing and reload subscription cleanup on 0.56.2.

Hypridle, Hyprlock, and Hyprpaper retain their `.conf` format. Hypridle still
needs the command changes below.

## 3. Migrate runtime callers with the config

| Caller | Required work |
| --- | --- |
| `hypr/scripts/displays.py` | Replace monitor keywords with `hyprctl eval`/`hl.monitor`; translate workspace moves; preserve extend, mirror, external-only, internal-only, hotplug, and remembered mode |
| `hypr/scripts/move-workspace.sh` | Translate workspace moves and monitor disable |
| `hypr/scripts/{workspace-cycle,workspace-group,workspace-layout,move-to-workspace}.sh` | Translate focus, workspace, grouping, movement, and layout dispatches |
| `.local/scripts/preview` | Translate monitor setup, focus, and silent window movement; preserve cleanup and reload |
| `hypr/hypridle.conf` | Translate DPMS commands for idle, resume, and after-sleep |
| `quickshell/endfield/panels/WorkspaceOverview.qml` | Translate workspace and window-focus dispatch expressions |
| `quickshell/endfield/panels/GroupBars.qml` | Translate focus and group-navigation dispatch expressions |
| Waybar/Quickshell native Hyprland integration | Use Waybar `ext/workspaces` protocol activation and verify Quickshell's Lua-aware workspace activation |

Keep the existing shell/Python responsibilities and CLI interfaces. Quote
dynamic workspace names, addresses, monitor descriptions, and selectors as
Lua data; do not concatenate unchecked strings into executable expressions.
Check IPC responses as well as process exit status.

## 4. Validate before cutover

1. Validate the candidate with `Hyprland --verify-config -c <candidate>`.
   First confirm the verifier cannot execute reload/startup side effects into
   the current desktop; isolate runtime context for candidate validation.
2. Run shell syntax checks and Python syntax checks for changed scripts.
   Add focused tests for dynamic Lua quoting and command translation where
   inputs make failures hard to detect visually.
3. Exercise a separate Lua compositor instance with an isolated runtime and
   explicit IPC target. Use tmux for interactive or long-running sessions.
   An extra headless output on the current compositor does not test a different
   config parser. Keep duplicate desktop services out of the isolated instance.
4. Verify configuration reloads update required modules and do not duplicate
   binds, event callbacks, services, or the display watcher.

## 5. Deploy and verify the real session

Prepare all config and caller changes before deployment. Lua callers cannot
be deployed piecemeal into the running legacy session. Quickshell reloads its
files automatically, and existing keybinds execute scripts from the live paths.

At a user-selected logout window:

1. Save a complete rollback copy outside directories managed by `deploy`:
   Hyprland, shared theme, Quickshell, and affected personal scripts. Prepare
   and verify a recovery command usable from a TTY/tmux session.
2. Stop the graphical session, then deploy the coordinated change with
   `./deploy hypr theme quickshell waybar` and `./deploy scripts`.
3. Inspect any deploy guard conflict. Legacy file removals themselves can
   trigger the guard; reconcile the exact files against the backup before an
   intentional forced deployment. Never force unrelated live changes away.
4. Validate the deployed `~/.config/hypr/hyprland.lua`, then start a fresh
   Hyprland session. Switching parser requires a restart, not a reload.
5. Compare live state with the baseline and run the acceptance checks below.

| Area | Acceptance checks |
| --- | --- |
| Config | No config errors; all required modules reload; effective settings match baseline |
| Shortcuts | Launchers, movement, grouping, screenshot commands, mouse drag/resize, media keys, overview selection on either Super-key release |
| Displays | Correct modes/scales/positions; workspaces 1–5 and `Laptop` on intended outputs; all four display modes; unplug/replug recovery |
| Shell | Overview, group tabs, sidebar, Waybar workspace interaction, and shell IPC work |
| Appearance | Palette, border alpha, animation timing, square corners, groupbar spacing match baseline |
| Lifecycle | One instance of each startup service/watcher after reload; lock/unlock, fallback Hyprlock, idle DPMS, suspend/resume work |
| Preview | Off-screen capture succeeds; output removal and reload restore workspace access |

Run visual checks through the migrated preview tool. Check lock state before
captures or synthetic input. Physical display switching, lock, and suspend
checks need a user-selected interruption window.

## 6. Cleanup and rollback

Remove obsolete Hyprland `.conf` modules after successful acceptance; retain
companion-tool configs and the Hyprlock palette. Update root and Quickshell
guides for Lua paths, palette copies, reload behavior, and new IPC syntax.
Document the minimum supported Hyprland version in provisioning; add a package
to `scripts/rice` only if the migration actually introduces that dependency.

On failure, stop the Lua session, restore the complete coordinated backup,
ensure the new `hyprland.lua` entry point is absent from the legacy recovery
configuration, and start a fresh session. Restoring only `hyprland.conf` is
insufficient: scripts, QML, and Hypridle commands also depend on the parser.

The active display policy stays hand-maintained in `displays.lua` and
`displays.py`. Generated nwg-displays output remains outside the loaded module
set; its different positions and HDMI mode are not part of the active policy.
Use Waybar's `ext/workspaces` module to activate workspaces through the
protocol supported by the installed 0.15.0 build.
